# GitCandy 架构设计

> 版本：v1.1 | 日期：2026-10-18 | 来源：代码结构分析

本文档描述 GitCandy 的分层架构、核心组件与关键流程。功能需求参见[需求文档](需求文档.md)，完成状态在[功能清单](功能清单.md)追踪。

## 1. 项目分层

```
GitCandy.slnx
├── GitCandy (GitCandy.Data)      ← 数据层 (.NET Standard 2.1)
│   ├── Entity/                    ← XCode 实体模型 (Model.xml) + 实体类 + Biz 业务逻辑
│   ├── Base/                      ← 基础工具类 (Pager, FileHelper, RegularExpression)
│   ├── Configuration/            ← [已排除] 旧配置模块
│   └── Security/                 ← [已排除] 旧安全模块 (Token)
│
├── GitCandy.Web                   ← Web 表现层 (.NET 10.0, ASP.NET Core MVC + Cube)
│   ├── Areas/GitCandy/           ← Cube 区域（后台管理）
│   │   ├── Controllers/          ← EntityController 魔方实体控制器
│   │   └── Views/                ← Razor 视图
│   ├── Controllers/              ← 自定义 Web 控制器（前台页面 + Git协议）
│   ├── Services/                 ← 应用服务（AccountService）
│   ├── Data/                     ← 数据服务（MembershipService, RepositoryService）
│   ├── Git/                      ← Git 核心访问层
│   │   └── Cache/                ← Git 缓存层
│   ├── Models/                   ← 视图模型
│   ├── Views/                    ← Razor 视图
│   ├── Extensions/               ← 扩展方法
│   └── wwwroot/                  ← 静态资源
│
├── Test                           ← 控制台测试项目 (.NET 8.0)
└── XUnitTest                      ← 单元/集成测试项目 (.NET 10.0)
```

### 依赖关系

```
GitCandy.Web → GitCandy（数据层）
GitCandy.Web → NewLife.Cube.Core（魔方框架）
GitCandy.Web → LibGit2Sharp（Git 操作库）
GitCandy → NewLife.XCode（ORM）

```

## 2. 数据层设计

### 2.1 实体模型（Model.xml）

| 实体 | 表名 | 主键 | 说明 |
|------|------|:--:|------|
| User | User | Int32 自增 | 用户/团队（通过 IsTeam 区分） |
| Repository | Repository | Int32 自增 | Git 仓库 |
| UserTeam | UserTeam | Int32 自增 | 用户↔团队 多对多关联 |
| UserRepository | UserRepository | Int32 自增 | 用户↔仓库 多对多权限关联 |
| GitHistory | GitHistory | Int64 | Git 操作审计日志 |

> **设计要点**：User 实体通过 `IsTeam` 字段同时承载「个人用户」和「团队」两种角色。团队也是特殊的用户，通过 `UserTeam` 关联表维护成员关系。链接字段 `LinkID` 用于关联 Cube 基础用户表。

### 2.2 实体 Biz 层

| 实体 | Biz 文件 | 核心方法 |
|------|----------|----------|
| User | 用户.Biz.cs | `Create`, `CreateTeam`, `Search`, `SearchByName`, `SearchTeam`, `SearchUser`, `GetOrAdd` |
| Repository | 仓库.Biz.cs | `FindByOwnerAndName`, `Search`, `GetPublics` |
| UserTeam | 用户团队.Biz.cs | `FindByUserAndTeam`, `Search`, `SearchSql` |
| UserRepository | 用户仓库.Biz.cs | `FindByUserIDAndRepositoryID`, `Search` |
| GitHistory | Git历史.Biz.cs | `Search` |

## 4. 关键流程

### 4.1 Git Smart HTTP 协议流程

```
Git Client (git push/pull/clone)
  │
  ├─ GET /{owner}/{project}.git/info/refs?service=git-upload-pack
  │    └─ GitController.Smart() → Basic Auth → GitService.InfoRefs()
  │
  └─ POST /{owner}/{project}.git/git-upload-pack
       └─ GitController.Smart() → Session Auth → GitService.ExecutePack()
```

### 4.2 Web 用户认证流程

```
浏览器请求
  └─ CandyControllerBase.OnActionExecuting()
       ├─ 检查 Session["GitToken"]
       ├─ 无Token → ManageProvider.Provider.TryLogin(HttpContext)
       ├─ 有Cube用户 → User.GetOrAdd(user) → 存入 Session
       └─ 设置 ViewBag.Token
```

### 4.3 仓库路由规则

```
/{owner}/{name}              → RepositoryController.Tree (默认)
/{owner}/{name}/{action}     → RepositoryController.{action}
/{owner}/{name}/{action}/{path} → RepositoryController.{action}(path)
/{owner}/{project}/{*verb}   → GitController.Smart (Git协议)
/{name}                      → AccountController.Detail (用户) 或 TeamController.Detail (团队)
```

## 5. 配置体系

`GitSetting` 继承 `Config<GitSetting>`，配置键前缀 `Git`，存储在 `appsettings.json`：

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| IsPublicServer | true | 是否开放服务 |
| AllowRegisterUser | true | 允许注册 |
| AllowRepositoryCreation | true | 允许创建代码库 |
| RepositoryPath | ../Repos | 代码库存储路径 |
| CachePath | ../Cache | 缓存路径 |
| GitCorePath | 自动探测 | git-core 路径 |
| Commits | 30 | 每页提交数 |
| PageSize | 30 | 分页大小 |
| Contributors | 50 | 显示参与者数 |
| AllowArchive | true | 允许打包下载 |
| AllowBlame | true | 允许查看审阅 |
| AllowCommits | true | 允许查看提交 |
| AllowContributors | true | 允许查看贡献者 |
| AllowHistoryDivergence | true | 允许查看分支差异 |
| AllowSummary | true | 允许查看摘要 |

## 6. 关键技术决策

| 决策 | 内容 | 理由 |
|------|------|------|
| User 实体承载用户+团队 | `IsTeam` 字段区分 | 简化模型，团队可像用户一样拥有仓库 |
| 本地用户表 + Cube 用户表分离 | `LinkID` 关联 | 保持 GitCandy 用户体系独立，同时复用 Cube 认证 |
| Git 操作使用外部 git.exe | `GitService.RunGitCmdAsync` | 利用 LibGit2Sharp 管理仓库元数据，git-core 处理传输协议 |
| 仅支持 HTTP 协议 | 不支持 SSH | 简化部署，无需管理 SSH Key |
| Cube 魔方做后台管理 | EntityController CRUD | 零代码获得 CRUD 界面，专注业务定制 |
